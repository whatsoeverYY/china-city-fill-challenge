# 视觉设计规范

本文件定义项目当前已经确认的视觉语言，是页面开发、组件重构和响应式适配的设计基线。它约束“看起来应该是什么样”，`docs/architecture.md` 约束“代码应该放在哪里”。视觉改动开始前必须同时阅读两份文档。

## 1. 设计基调

整体视觉是“纸上地图、城市印章、编辑式图鉴”，不是通用 SaaS 后台，也不是高饱和游戏 UI。

- 使用暖纸色背景、深墨色正文和低透明度网格，营造地图册与知识卡片的质感。
- 中文大标题使用宋体风格，正文使用清晰的无衬线字体，数字使用独立的衬线数字字体。
- 模块通过稳定的主题色区分，但共享相同的纸张、边框、圆角、阴影和排版语言。
- 大卡片和印章允许一个较小的左下角，形成项目特有的不对称轮廓；不能把所有组件改成普通的等圆角矩形。
- 桌面端信息密度、尺寸和布局是视觉契约。移动端要重新安排信息优先级，但不能反向改变桌面端。
- 装饰服务于层级：同一屏不堆叠多种渐变、强阴影或高饱和颜色。

## 2. 设计来源与实现边界

视觉实现的权威来源按以下顺序确定：

1. 本文件定义语义和使用规则。
2. `tailwind.config.ts` 定义色阶、语义色、可复用渐变和阴影。
3. `src/app/globals.css` 定义字体、纸张背景、全局焦点样式和降级动画。
4. `src/shared/config/map-colors.ts` 定义必须以数值形式传给 SVG、Canvas 或地图引擎的颜色。
5. Feature `config/` 中的样式映射负责稳定 ID 到样式的关联。

常规布局、颜色、排版、状态和响应式规则优先写成 Tailwind utility。只有复杂关键帧、SVG 固有表现或 Tailwind 无法稳定表达的组合效果才使用语义 class + CSS。

禁止事项：

- 不在 TSX 中写十六进制颜色。
- 不根据中文标题、按钮文案或数组位置选择颜色。
- 不用 `@apply` 或大型 `*-styles.ts` 隐藏一套新的集中样式表。
- 不为了“统一”而把已有的模块色全部替换成同一种颜色。
- 不在重构时顺便改变字号、圆角、阴影、间距或信息密度。

## 3. 颜色系统

### 3.1 中性色基础

所有页面先使用中性色建立层级，再增加模块色。

| 语义 | 推荐 token | 用途 |
| --- | --- | --- |
| 页面底色 | `bg-paper` | 全局暖纸色背景 |
| 浮层/卡片 | `bg-card`、`bg-paper-100` | 卡片、面板、弹窗 |
| 加深纸色 | `bg-paper-deep`、`paper-500` 至 `paper-900` | 分区、轨道、弱边界 |
| 主文字 | `text-ink`、`ink-900` | 标题、正文、关键数字 |
| 次文字 | `text-ink-soft`、`ink-500` 至 `ink-700` | 描述、元信息、占位说明 |
| 弱边框 | `border-black/10` 至 `border-black/15` | 中性卡片和模块分隔 |
| 辅助灰 | `stone-*` | 禁用、辅助标签、非业务重点 |

大面积纯白和纯黑会破坏纸张质感，除图标反白、遮罩或高对比状态外不作为主要表面。

### 3.2 品牌与模块色

每个命名色板都必须保留 `100` 至 `900` 九档。下表的 500 档用于识别色板，实际组件根据对比度选择不同档位。

| 色板 | 500 档 | 语义 |
| --- | --- | --- |
| `city` | `#b43b32` | 系统品牌主色、省界、主行动、强调 |
| `jade` | `#2d7d5f` | 城市边界、邻省、正确、地域关联 |
| `atlas` | `#356b8e` | 全国图鉴、地图路线、信息型内容 |
| `scholar` | `#735285` | 地理知识馆、学习与知识专题 |
| `gold` | `#d5a945` | 过关斩将、成就、重点数字、焦点 |
| `clay` | `#a15d3a` | 疆域、土地、偏暖地理专题 |
| `navy` | `#355f91` | 较强的信息与路线状态 |
| `moss` | `#47765d` | 低饱和自然辅助色 |
| `olive` | `#567b3d` | 高校、植被和地域辅助色 |
| `ink` | `#777d78` | 墨色中间阶，不替代 `text-ink` 主文字 |
| `paper` | `#ede7d8` | 纸张层级 |
| `stone` | `#969087` | 中性辅助层级 |

色阶选择遵循统一语义：

- `100–200`：浅色表面、弱选中背景、低对比装饰。
- `300–400`：悬停表面、进度轨道、地图浅填充。
- `500`：默认识别色、图标底色、标准边界。
- `600–700`：浅底上的文字、强调边框、悬停或选中状态。
- `800–900`：高对比文字、强状态、深色按钮。

### 3.3 颜色选择顺序

新增组件按以下顺序选色：

1. 使用 `paper/card + ink` 建立基础层级。
2. 选择当前模块的唯一主色。
3. 必要时增加一个有明确含义的辅助色。
4. 成功、错误、离线等状态色优先于模块色。
5. SVG 和地图保持固定地理语义，不跟随卡片主题随意换色。

单张卡片一般只使用一个模块主色；最多增加一个辅助色。文字、边框、图标和浅底应来自同一色板的不同档位，不拼接无语义的彩虹色。

### 3.4 模块配色

| 模块 | 主色 | 辅助色 | 固定语义 |
| --- | --- | --- | --- |
| 城市填图 | `city` | `jade`、`gold` | 省界为红，地市/区县界为绿，完成强调可用金色 |
| 全国车牌图鉴 | `atlas` | `navy`、`city` | 蓝色承担图鉴和路线，车牌关键字符可使用品牌红 |
| 地理知识馆 | `scholar` | 专题 tone | 知识馆框架用紫色，专题卡按稳定 `tone` 使用红/绿/蓝/金/紫 |
| 过关斩将 | `gold`、`city` | 关卡语义色 | 关卡徽章通过稳定关卡 ID 映射，不按标题或顺序匹配 |
| 管理/账户 | `ink`、`paper` | `status-*` | 成功、错误、离线和空闲使用语义状态色 |

`level-*` 和 `status-*` 是语义色，不作为任意装饰色使用。新增状态或关卡时先补稳定 ID 与映射，再在组件中引用 class。

## 4. 字体与字号

### 4.1 字体角色

- `font-sans`：正文、表单、按钮、标签和操作说明。
- `font-serif`：页面主标题、卡片标题、品牌印章、具有编辑感的强调文字。
- `font-numeric`：大数字、进度、排名、统计和关卡编号。

不要整页使用宋体，也不要把大标题改成普通无衬线粗体。英文小标题和缩写可使用无衬线字体配合字距。

### 4.2 字号层级

| 层级 | 桌面建议 | 移动建议 | 用途 |
| --- | --- | --- | --- |
| 超大展示标题 | `42–82px` | `30–36px` | 知识馆或专题首页 Hero |
| 页面主标题 | `34–58px` | `28–34px` | 模块标题、关卡首页标题 |
| 区块标题 | `25–39px` | `21–28px` | 内容分区 |
| 卡片标题 | `18–28px` | `16–20px` | 关卡卡片、专题卡片 |
| 正文/引导 | `13–15px` | `12–14px` | 说明和主要内容 |
| 紧凑正文 | `11–13px` | `10–12px` | 列表、地图说明、按钮 |
| 元信息 | `8–11px` | `8–10px` | 计数、关卡关联、辅助状态 |

规则：

- 页面标题行高通常为 `1.03–1.12`，正文行高为 `1.7–1.9`。
- 正文不得为了塞进卡片而低于 `11px`；低于 `11px` 的文字只能是非关键元信息。
- Eyebrow 使用 `9–11px`、粗体和 `0.12em–0.24em` 字距，不承载长句。
- 大数字可比相邻文字高 2–3 个层级，但必须配清晰单位或标签。
- 移动端不是按比例缩小桌面字号，而是重新选择对应层级。

## 5. 布局与间距

### 5.1 页面宽度

- 主游戏壳：`min(1460px, 100% - 48px)`。
- 内容型模块：通常不超过 `1380px`。
- 长段说明：正文阅读宽度控制在 `780–900px`。
- 手机外边距统一为 `12px`，即内容宽度约为 `100% - 24px`。

### 5.2 间距节奏

- 页面大区块：`48–90px`。
- Hero 内部：`15–30px`。
- 桌面卡片网格：`16–22px`。
- 移动卡片网格：`8–12px`。
- 卡片内边距：桌面 `20–30px`，移动 `12–16px`。
- 紧密排列优先使用 `6/8/10/12px`，不要出现没有规律的相邻间距。

内容层级用留白表达，避免为每一层都增加边框或背景色。

## 6. 形状、表面与阴影

### 6.1 圆角体系

| 元素 | 建议形状 |
| --- | --- |
| 品牌印章 | `9px 9px 9px 3px`，允许轻微旋转 |
| 专题图标/关卡徽章 | `16–24px 16–24px 16–24px 5–8px` |
| 大卡片/模块卡片 | `20–28px`；编辑式卡片优先缩小左下角 |
| 普通面板/地图图例 | `12–16px` |
| 输入框/紧凑操作 | `10–15px` |
| Tag、状态胶囊 | `rounded-full` |

同一组件族必须共享轮廓。不要在相邻卡片中随意混用直角、标准圆角和胶囊形。

### 6.2 表面

- 主卡片使用 `bg-card/80–95` 或 `bg-paper-100/90`，保留纸张底色透出。
- 边框优先 `border-black/10–15`；有模块语义时用对应色板 `/20–35`。
- 淡色径向渐变只用于 Hero、专题卡或大型关卡卡，方向通常从右上角进入。
- 不使用大面积玻璃拟态、霓虹发光或纯冷灰后台风格。

### 6.3 阴影

- 小卡片使用低透明暖灰阴影，主要表达纸片层级。
- 大卡片可使用约 `0 22–30px 42–70px` 的柔和阴影。
- 彩色阴影只用于对应 tone 的悬停反馈，且透明度保持克制。
- 同一个视觉效果复用两次以上时放入 `tailwind.config.ts`，不要复制任意阴影字符串。

## 7. Tag、徽章与标签

项目区分四种小型标记：

### 7.1 Eyebrow

不带容器的章节标签，用于标题上方。使用模块色、粗体和较大字距，长度控制在一行短语。

### 7.2 信息 Tag

- 形状为胶囊，浅色背景 + 同色系文字 + `20–30%` 边框。
- 字号 `9–11px`，字重 `700–900`，水平内边距 `8–12px`。
- 只放简短分类、数量或筛选状态，不放句子。
- 多个 Tag 同时出现时保持同一高度和间距。

### 7.3 状态 Tag

- 强状态使用实色底和高对比文字；弱状态使用浅底。
- 成功、错误、离线、空闲使用 `status-*`，不借用模块色假装状态色。
- 除颜色外必须有文字、图标或形状差异，不能只靠颜色传达状态。

### 7.4 大徽章

关卡、专题和品牌徽章使用不对称圆角、衬线字体和轻微内描边。桌面通常为 `58–74px`，移动为 `44–48px`。徽章颜色必须来自稳定 ID 映射。

## 8. 按钮设计

### 8.1 按钮层级

| 类型 | 样式 | 场景 |
| --- | --- | --- |
| 主按钮 | 模块色或 `city-500` 实色底，高对比文字 | 每个区域唯一的主要动作 |
| 次按钮 | 浅模块色底、同色边框和深色文字 | 设置、筛选、次级导航 |
| 中性按钮 | `paper/card` 表面、弱边框、墨色文字 | 返回、取消、通用操作 |
| 危险/强警告 | `city-900` 或明确错误语义 | 删除、不可逆或高风险动作 |
| 图标按钮 | 明确的 40–44px 点击区和 `aria-label` | 空间有限的辅助操作 |

### 8.2 尺寸与交互

- 桌面紧凑按钮最小高度 `38–40px`。
- 移动端所有主要点击区域最小高度和宽度为 `44px`。
- 胶囊按钮用于模块入口、切换和短操作；长文本操作使用 `10–15px` 圆角矩形。
- Hover 只做轻微上移、边框加深或背景加深，通常不超过 `1–2px`；大型卡片可上移 `4–5px`。
- Active 应回到接近原位，避免点击时漂浮。
- Focus 使用全局金色轮廓，不能用 `outline-none` 移除。
- Disabled 必须同时改变透明度和光标，并保持文案可读。
- 开关按钮使用 `aria-pressed` 或 `role="switch" + aria-checked`。

一个操作区只保留一个最高视觉优先级的主按钮，不能让所有按钮都成为实色主按钮。

## 9. 链接与导航

- 正文链接使用当前模块的 `600–700` 档，Hover/Focus 增加下划线或明显的色阶变化。
- 页面入口链接可以做成按钮或卡片，此时必须使用 `no-underline`，并提供完整点击区域。
- 顶部模块入口使用各自模块色，不能全部变成品牌红；图标圆、浅色底和文字来自同一色板。
- 返回链接和面包屑保持中性或使用当前模块色，不与主按钮争夺注意力。
- 外部链接在上下文不明确时增加文字或图标提示。
- 只显示箭头的链接必须有可访问名称；不能只靠 `→` 表达目的地。

## 10. 表单与反馈

- 输入框使用纸色/卡片表面、`10–15px` 圆角和清晰边框。
- 默认边框为中性弱边框；Focus 使用当前模块色，同时保留全局可见焦点。
- Label 始终可见；Placeholder 不能代替 Label。
- 错误信息靠近字段，使用错误语义色并说明如何修复。
- 成功反馈优先短暂提示或局部状态变化，不用高饱和整屏提示。
- 地图答题、闯关反馈可使用短动画，但必须支持 `prefers-reduced-motion`。

## 11. 模块与页面结构

主要模块优先按以下结构组织，按业务需要省略而不是随意重排：

1. **品牌 Header**：品牌印章、模块入口/返回、主要状态或进度。
2. **Hero/导语**：Eyebrow、宋体主标题、简短说明；一个屏幕只保留一个主视觉标题。
3. **设置或统计带**：低高度、弱背景，不压过核心内容。
4. **主工作区**：地图、题面或内容网格；桌面突出主要任务，辅助面板放右侧。
5. **反馈与操作区**：紧贴当前任务，避免跨屏寻找按钮。
6. **移动端固定/粘性操作**：只保留高频动作，不复制整套桌面 Header。

模块之间通过主色区分，通过以下内容保持同一产品感：

- 暖纸底和墨色正文。
- 品牌印章与不对称卡片轮廓。
- 宋体标题、无衬线正文和数字字体分工。
- 弱边框、柔和阴影和克制的径向渐变。
- 相同的按钮、Tag、焦点和移动触控规则。

## 12. 地图与数据可视化

- 省级边界固定使用 `city` 红色语义，地市/区县边界固定使用 `jade` 绿色语义。
- 正确、错误、当前、目标、路线和中性区域的颜色从 `MAP_COLORS` 读取。
- 地图标签必须有足够对比度；复杂底图上使用描边或浅色轮廓提高可读性。
- 图例中的颜色、线宽和填充必须与地图一致。
- 地图颜色不参与普通卡片 tone 轮换。
- 排名、进度和比较图优先使用长度、位置和文字，同时用颜色加强，不只靠颜色区分。

## 13. 响应式设计

本项目以已确认的桌面样式为默认视觉契约，移动适配通过 `max-*` 断点隔离。

### 13.1 桌面端

- 默认布局适用于宽桌面；`1050/1200px` 左右可收紧 Header 或网格，但不改变视觉语言。
- 地图/题面是主区域，右侧面板宽度通常为 `310–360px`。
- 保持信息密度，不因为增加移动端样式而隐藏桌面说明或压缩卡片。

### 13.2 平板与手机

- `641–900px`：从多栏过渡到单栏或紧凑双栏，重新安排辅助面板顺序。
- `≤640px`：按手机重新设计，页面外边距 12px，主要触控区至少 44px。
- 核心任务使用单列；关卡等短卡片可以双列，但每张卡仍需有足够点击宽度。
- 次要描述可以隐藏，关键状态、题目、反馈和主要动作不能隐藏。
- 地图必须保留可操作高度，避免被 Header、底部工具栏和浏览器安全区挤压。
- 长列表和选择器使用明确的内部滚动区，页面不能产生横向滚动。
- 闯关中的移动导航可以粘在顶部，并省略桌面品牌 Header；这属于移动端独立设计，不是桌面缩小版。

任何响应式修改都必须同时验证至少一个桌面视口和 `390 × 844` 手机视口，并检查 `scrollWidth <= innerWidth`。

## 14. 可访问性与动效

- 正文和关键操作必须满足清晰对比度，浅色文字不能直接放在浅色背景上。
- 所有可点击非文本元素必须有可访问名称。
- 状态不能只靠颜色表示。
- 键盘焦点必须可见，Tab 顺序与视觉顺序一致。
- 动画时长短、幅度小；错误摇动只用于即时答题反馈。
- `prefers-reduced-motion` 下关闭非必要动画和滚动行为。

## 15. 开发与 Review 清单

新增或修改 UI 时逐项确认：

- [ ] 使用了现有命名色板，没有在 TSX 写十六进制颜色。
- [ ] 模块主色和状态色语义正确，没有按显示文案选择样式。
- [ ] 标题、正文、数字使用了正确字体角色和字号层级。
